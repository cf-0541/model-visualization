# 回放准备与随机跳转基准

在项目根目录运行：

```powershell
pnpm bench:trace
pnpm bench:trace:prepare
pnpm bench:trace:checkpoint
```

## 随机跳转

`seek.mjs` 从真正的 TraceRuntime 捕获 3,902 条事件，构造 127 次确定性跳转，包含尾部来回拖动、回到开头、跨段前进；逐次比较启用 / 禁用检查点得到的完整 VisualStep。两者使用同一事件、帧选择和回放状态机，关闭检查点的一侧仍从头回放。

计时包含创建游标并定位结尾的准备过程；分别报告初次定位和整组跳转的 7 次中位数。断言使用结果一致性、应用事件数减少和缓存预算，不用机器相关毫秒数决定 CI 成败。

默认每 256 个事件保存状态，最多 12 份，复制时同步累计保守 JSON UTF-8 字节上界，预算 1 MiB（不是精确序列化大小）；单份超预算则提前停止复制、不保存，数量 / 大小超预算时淘汰较早缓存。缓存包括读依赖尾部、分支、完整调用栈、惰性数组写入以及已追踪值，而不是仅保存屏幕快照；恢复时复制，避免后续写入污染历史。

2026-11-16 Windows 本地复测：无检查点约 129ms，启用约 14ms（整组跳转）；应用事件数 409,707 → 35,947，12 个检查点约 8,085 B 序列化数据。数字受机器、负载、运行版本影响，请以复测输出为准。

这是 Vite SSR 下的本地微基准，**不是浏览器 FPS、单次用户点击延迟或 JS 堆内存测量**。保守字节计费预算不能承诺实际堆内存不超过 1 MiB。正式页面的停止、恢复及回退由生产 UI 测试另外验证。

## 准备开销

`measure.mjs` 比较旧的 `compileTrace + selectDpTarget` 与 `selectDpTargetFromEvents`。含一组故意超过运行时初始快照预算的 120×120 合成数据及一组实际受限捕获数据，两组不能混为真实应用输入。输出 JSON 大小仅代表序列化体积，不是 JS 堆用量。

本轮不提高 4,000 事件 / 10,000 次循环 / 2.5 秒的 JS 运行限额，也不扩大可信代码的安全承诺。

## 2026-11-18：检查点计费与定位边界

原 `next` 表示原事件数组中「下一待应用事件」的绝对位置，而非历史累计回放次数。键 `k` 保存应用完 `[0, k)` 的状态，恢复后从 `events[k]` 继续；倒回不会让键和事件位置脱钩。新增间隔 1 / 2 / 7 / 16 / 256 的边界、淘汰及确定性随机跳转测试，在修改前已经通过；此次仅明确命名 / 注释，不作为正确性修复。

`checkpoint.mjs` 将 `361ad0d` 的复制 + JSON.stringify + TextEncoder 与新的一次遍历复制计费对照，使用相同数据 / 1 MiB 预算，比较成功保存的内容，并校验新计费不低于精确 JSON 字节数。每组报告 16 个候选点、7 次中位数，不以毫秒作为测试门槛。

新计费按字符串每 UTF-16 单元至多 6 字节、数字至多 32 字节等保守界累计，不分配整份 JSON / 编码缓冲，超预算提前停止。它**不是精确字节大小，也不是堆内存测量**；同一数据的计费数字可能明显变大，接近预算时缓存份数可能减少。旧记录 8,085 B 是精确序列化计量，不可直接与新计费 70,676 B 比较来判断内存增长。

本地首次微基准：120 数字数组旧 / 新约 0.12 / 0.27ms；合成 120×120 网格约 7.56 / 4.52ms；超过 1 MiB 的合成字符串约 54.30 / 0.01ms（均为 16 个候选点）。**小数据并不更快**，主要收益是避免整份编码分配及超预算提前退出。合成数据不代表实际运行时一定能产生这些快照。请以复测输出为准。

新计费下，同一 3,902 事件 / 127 次跳转本地约 140 / 16ms（禁用 / 启用检查点），仍保留 12 份，应用事件数仍为 409,707 / 35,947。该对比是本轮有无缓存差异，不是相对旧计费版本的加速倍数。
