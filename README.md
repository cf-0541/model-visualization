# Algorithm Motion Lab

由**真实 JavaScript 执行轨迹**驱动的算法动画。粘贴函数或完整脚本，系统插桩后在 Web Worker 中运行，再把数组读写、动态规划状态、线段树递归和图的邻接表遍历编译为可逐步播放的视图。

## 功能

- 自动识别模型：优先采用 `@model` / `__model` 显式声明，其次分析队列与邻接遍历、区间递归、状态依赖等代码结构，再参考执行轨迹；识别依据会在界面显示，不确定时返回 `unknown`、保留轨迹并提醒手动选择结构，不再默认展示数组动画。
- 四类视图：数组 / 排序、一维或二维 DP、线段树、邻接表图遍历（含队列、访问状态）。重命名的 DP 状态数组会依据实际读写选择，而非仅靠变量名。
- 不强制 `solve(input)`：直接运行普通函数声明、`const` / `var` 函数表达式或箭头函数；优先 `solve`，否则优先非辅助函数，最后取第一个函数。支持多参数按顺序传入。
- 可粘贴已包含顶层调用的完整脚本：只运行一次，结果取最后的顶层表达式或变量初始化；此时输入框不参与调用。
- 输入支持 JSON 及安全的 JavaScript 字面量（单引号、未加引号的对象键、逗号分隔的位置参数）；输入中的变量和函数调用**不会求值**。
- 代码与模型同步展示：逐行高亮仅滚动代码框；窄屏优先呈现紧凑轨迹与模型。支持默认关键帧与可切换的全程事件、递归调用栈、播放 / 暂停 / 单步 / 时间轴 / 倍速控制。
- 内置打家劫舍、二维网格路径、冒泡排序、线段树、BFS 双参数和 LeetCode 两数之和模板。
- 一键复制分享链接：将当前代码、输入和模型选择编码到 URL hash；打开链接只载入内容，**不会自动运行**。

## 运行

需要 Node.js 与 pnpm，在项目根目录执行：

```powershell
pnpm install
pnpm dev
```

打开 Vite 显示的本地地址，点击“运行并生成动画”开始；初次打开仅载入示例，不自动执行，Babel 解析与插桩代码在首次运行时按需加载。验证：

```powershell
pnpm test
pnpm build
```

## 粘贴代码与输入

例如直接粘贴常见的 BFS 函数签名：

```js
function bfs(adj, start) {
  const queue = [start];
  const seen = Array(adj.length).fill(false);
  seen[start] = true;
  while (queue.length) {
    const node = queue.shift();
    for (const next of adj[node]) {
      if (!seen[next]) {
        seen[next] = true;
        queue.push(next);
      }
    }
  }
  return seen;
}
```

双参数输入可以是按顺序排列的数组 `[[[1], [0]], 0]`，也可以是同名对象 `{adj: [[1], [0]], start: 0}`；单参数函数直接输入该参数的值，例如 `[7, 3, 5, 1]`。也可输入 JavaScript 字面量（如单引号字符串），但不支持变量引用、任意表达式或输入里的函数调用。

想明确指定模型时，在代码里加一处声明即可：

```js
// @model graph
```

或：

```js
export const __model = 'graph';
```

允许的值：`array`、`dp`、`segment-tree`、`graph`。声明只用于选择视图，`export const __model` 会在执行前转换为普通声明；菜单中的**手动选择优先级最高**。声明与真实数据结构不符时，视图也无法保证正确，请在运行后核对轨迹和图形。

完整脚本示例：

```js
function add(a, b) { return a + b; }
add(2, 3);
```

脚本的调用已在代码里，**不会再次调用入口**；结果栏显示 `5`。完整脚本模式忽略输入框，请把测试数据直接写在脚本里。当前只支持同步、可独立执行的 JavaScript；不支持 `import`、`export default`、TypeScript 类型、`async` / Promise。带 `export` 的普通命名声明可在运行前展开，但依赖其他模块的代码仍需自行补齐。

## 执行与安全

```text
代码 + 字面量输入 → Babel AST 插桩 → Web Worker 执行
                 → 轨迹事件 → 模型选择 / 状态快照 → React / SVG 动画
```

Worker 设置 2.5 秒超时、4,000 条事件和 10,000 次循环迭代上限；触顶会停止运行、保留部分轨迹并明确标记“已截断”，不能把部分轨迹当成完整结果。单次数据快照和观察对象数量有边界；长轨迹的编译快照最多保留 400 帧；播放支持按信息量选择的关键帧和完整逐事件回放，跳帧间的状态仍会依序更新。上述限制降低普通大输入的卡顿风险，但不保证任意代码都不会耗尽资源；**Worker 不是恶意代码安全沙箱**。只运行自己信任的脚本。分享链接里的源码和输入明文可还原；不要放密码、Token 或个人隐私，也要考虑链接可能进入浏览器历史、聊天软件或服务日志。

当前没有对任意算法“必然识别正确”的保证；结构不够明确时不会猜成数组，仍可查看轨迹并手动选择视图。离线保存和图片导出留待后续优化。
